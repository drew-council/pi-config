# Releases

A release is a GitHub release whose tag triggers the production deploy through Google Cloud Build. Tags follow CalVer: `vYYYY-MM-DD.N`, where N counts deploys that day starting at 0, and hotfixes append `-hotfix`. The wiki pages "Production Release Process" and "Production Hotfix Release Process" are the full runbooks.

## What a release looks like

- The tag targets a specific commit, not `main`.
- Release notes are generated by GitHub from `.github/release.yml`, which groups merged PRs by label: `highlight`, everything else, `internal`, `dependencies`. Fix a wrong section by relabeling the PR and regenerating, not by editing the notes.
- Publishing posts to the Releases chat room and starts the build. Someone with approval rights then approves the Cloud Build deploy.
- Never delete or reuse a tag. To abandon a release, delete the release, keep the tag, and cut the next one with a fresh number using the last good tag as the previous tag for notes.

## Commands

```sh
release.sh list                      # recent releases
release.sh show v2026-09-15.1        # notes
release.sh contains 28335            # is that PR's merge commit in the latest release? exit 0 yes, 1 no
release.sh contains 28335 v2026-09-14.2
release.sh first 28335               # earliest release with the change
release.sh next-tag                  # next CalVer tag for today
release.sh draft --target <sha>      # draft release with generated notes; never publishes
```

"Is this deployed?" means `release.sh contains <pr>` plus checking that the Cloud Build for that tag finished. The build console is go/build.

Publishing a release deploys to production. Draft it, show the user, and let them publish.
